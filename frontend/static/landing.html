一个反直觉的发现：把整段视频直接丢给多模态模型，画面类问题反而更差 （相关性 0.801 vs 0.872）——模型要在十几分钟里自己找"该看哪一帧"， 而帧知直接把你暂停的那一帧放到它眼前。 轻量路线不是妥协，是更优解。

三步上手

会复制粘贴命令就行

起一个后端

克隆仓库，配好模型 API Key（DeepSeek / 通义百炼等），一条命令起服务：

docker-compose up -d

装浏览器插件

下载仓库里的 extension 目录 → Chrome 打开 chrome://extensions → 开启开发者模式 → 「加载已解压的扩展程序」。

打开B站视频提问

插件设置里填后端地址（本地默认 http://localhost:8123）， 随便打开一个B站学习视频，点悬浮按钮开问。

没有服务器？后端也可以部署在任意一台你能访问的机器上（1核1G 的最低配云主机即可， 模型调用走你自己的 API Key，服务器只负责调度）。部署方式见仓库 README。

常见问题

—

要花多少钱？

项目本身开源免费。运行时花费的是模型 API 调用费（你自己的 Key）， 每次提问的字幕+单帧分析成本约 ¥0.02 量级——因为设计上就用廉价的文本 token 覆盖大部分问题， 只在真需要看画面时才付视觉成本。

我的数据在哪？

全部在你自己部署的后端里：字幕、索引、对话记录、笔记、长期记忆都存在本地 SQLite 和文件系统， 不经过任何第三方中转。模型调用也只是把提问相关内容发给你的模型服务商。

支持哪些视频？

支持B站视频（自动获取字幕，无字幕视频可开启语音转写），也可以直接粘贴视频链接（B站/YouTube 等）解析。 更多平台在计划中，欢迎提 issue。

它会不会一本正经地胡说？

评测集里 16 道"视频里根本没有答案"的陷阱题，拒答率 100%——回答尽量只基于视频实际内容， 查不到依据就说没有。当然，AI 不可能完美，时间戳引用能帮你快速核实。
