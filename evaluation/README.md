## 问题类型（评测集的核心设计）

不只测「字幕能答的问题」，而是**覆盖能力边界**，让不同架构的差距显性化：

| 类型 | 定义 | 考察 | 需要视觉 |
|---|---|---|---|
| `single_hop` | 答案在单段字幕中直接可答 | 基础检索 | ❌ |
| `multi_hop` | 需综合多段字幕 | 跨片段检索+综合 | ❌ |
| `visual_only` | 答案只在画面里，字幕没有 | 视觉理解 | ✅ |
| `joint` | 需字幕 + 画面结合 | 多模态联合 | ✅ |
| `unanswerable` | 视频根本没讲过，应拒答 | 幻觉抑制 | 视情况 |

**示例**：
- `visual_only`：「主讲人身上穿的短袖 T 恤是什么颜色？」
- `unanswerable`：「主讲人佩戴的眼镜是什么品牌？」

这类问题**只看字幕的系统和多模态系统的差距会立刻显现**。


## 评测结果（v2，2026-09-12）

> ⚠️ **v2 相对 v1.1 是数据修正后的重跑**：此前评测用的字幕实为 ASR 结果
> （因缓存被 ASR 覆盖），文本含识别错误、时间轴被非均匀拉伸约 1.44 倍。
> 修正为 B站官方字幕后全部与视频时长对齐，**所有指标已重跑**。
> 详见文末「修订记录」——这次修正让若干结论发生了方向性变化。

### V1：纯字幕 RAG（检索 Top5 → LLM 生成）

**检索层**

`multi_hop` 的 `time_start`/`time_end` 为**并列列表**（按索引一一对应多个答案片段），
因此额外报告**片段覆盖率**与**全片段命中率**。

| 问题类型 | R@1 | R@5 | MRR | 片段覆盖 | 全片段命中 |
|---|---|---|---|---|---|
| single_hop | 0.375 | 0.750 | 0.552 | 0.750 | 0.750 |
| multi_hop | 0.562 | **0.938** | 0.729 | 0.707 | **0.500** |
| joint | 0.375 | 0.562 | 0.453 | 0.562 | 0.562 |
| visual_only | 0.438 | 0.562 | 0.500 | 0.562 | 0.562 |
| **主战场合计**（前 3 类） | 0.437 | **0.750** | 0.578 | | |

**生成层**

| 问题类型 | 忠实度 | 相关性 | 引用准确率 | 拒答率 |
|---|---|---|---|---|
| single_hop | 0.759 | 0.906 | 0.750 | — |
| multi_hop | 0.772 | 0.831 | **1.000** | — |
| joint | 0.632 | 0.781 | 0.533 | — |
| visual_only | 0.529 | **0.188** | 0.533 | — |
| unanswerable | — | — | — | **1.000** |

### V2：全量字幕注入（不检索，整段字幕进上下文）

字幕作为 `<transcript>` 消息注入（固定前缀 → 命中前缀缓存）。

| 问题类型 | 忠实度 | 相关性 | 引用准确率 | 拒答率 |
|---|---|---|---|---|
| single_hop | 0.870 | 0.894 | 0.875 | — |
| multi_hop | 0.809 | 0.863 | **1.000** | — |
| joint | 0.722 | **0.906** | 0.625 | — |
| visual_only | 0.736 | 0.312 | 0.429 | — |
| unanswerable | — | — | — | **1.000** |

**V1 → V2**：质量 12 项中胜 9 项（忠实度 4/4 全胜）；
等效成本 **540 vs 2253 tokens（仅 24%）**——因字幕固定不变可命中前缀缓存（92%）。

### V3：全量字幕 + 固定视觉（每题都分析画面）

在 V2 基础上，每题分析「用户暂停点」那一帧（取题目 `time_start` 模拟暂停位置）。

| 问题类型 | 忠实度 | 相关性 | 引用准确率 | 拒答率 |
|---|---|---|---|---|
| single_hop | 0.886 | **0.969** | 0.750 | — |
| multi_hop | **0.911** | 0.863 | 0.933 | — |
| joint | 0.781 | 0.863 | 0.667 | — |
| visual_only | 0.822 | **0.634** | 0.667 | — |
| unanswerable | — | — | — | **1.000** |

**V2 → V3**：忠实度 4/4 全面上升；
**`visual_only` 相关性 0.312 → 0.634（+103%）**——视觉能力对「只能靠画面回答」的问题效果显著。
代价：等效 540 → **948 tokens（+76%）**，延迟 6.9s → 7.9s。

### 三条关键结论

1. **相关性随视觉依赖度递减，断崖只出现在纯视觉场景**
   V1：`0.906 → 0.831 → 0.781 → 0.188`
   字幕可答 / 跨片段 / 字幕+画面三类都还不错，**真正无法覆盖的是「只能靠画面回答」**。

2. **全量字幕优于 RAG，但是「稳定小幅领先」而非「碾压」**
   质量 9/12 胜、成本仅 24%。成本优势来自前缀缓存（字幕固定不变）。
   > 注：数据修正前曾测出「10/11 胜、multi_hop 忠实度 +89%」，
   > 那主要是**错误字幕对 RAG 的伤害远大于对全量字幕**造成的假象。

3. **视觉能力有效，但要付成本**
   `visual_only` 相关性翻倍（0.312 → 0.634），代价是每题多一次视觉调用（成本 +76%、延迟 +1s）。
   → 这正是「固定调视觉」与「Agent 自主决定何时调」要对比的取舍。

## 已知局限（使用时请注意）

| 项 | 说明 |
|---|---|
| **字幕为 B站官方字幕** | 官方 AI 字幕仍可能有少量识别错误（如 `numpy`→`南派`） |
| **部分标注待复查** | 已发现并修正 6 条超出视频时长的标注；可能仍有偏差的（见修订记录） |
| **judge 与被评模型同源** | LLM-as-judge 有自评偏差，且**单次判定有随机性**（已用多数投票降低） |
| **V3 的暂停点假设** | 用题目 `time_start` 模拟「用户暂停位置」，是给系统的一点提示 |
| **字幕平均仅 4,128 tokens** | 视频 10-20 分钟，是全量字幕方案最有利的场景，长视频结论不能直接外推 |

### 修订记录

- **v2（2026-09-12）**：**字幕修正为 B站官方字幕**后全部重跑。
  此前字幕实为 ASR 结果（官方字幕与 ASR 写同一缓存，ASR 完成更晚、直接覆盖），
  文本含识别错误、时间轴被非均匀拉伸约 1.44 倍。
  修正后若干结论发生**方向性变化**：
  - `multi_hop` 全片段命中 0.125 → **0.500**，忠实度 0.414 → **0.772**
  - 「跨片段检索是结构性短板」的结论**程度被严重高估**
  - 「全量字幕碾压 RAG」的结论**收窄为小幅领先**
- **v1.1（2026-09-12）**：`multi_hop` 由单一宽区间改为并列多片段区间，
  修正两处指标虚高（检索 R@5 0.812→0.625、引用准确 0.800→0.500）。
- v1（2026-09-11）：首版基线。

## 复现方式

```bash
# 评测集
python evaluation/build_dataset.py          # 从 markdown 评测集构建 dataset.json

# V1 纯字幕 RAG
python evaluation/eval_retrieval.py         # 检索层（约 3s）
python evaluation/eval_generation.py        # 生成层（约 14min，消耗 token）

# V2 全量字幕注入（不检索）
python evaluation/eval_full_context.py      # 约 17min

# V3 全量字幕 + 固定视觉
python evaluation/eval_v3_full_vision.py    # 约 20min（含抽帧）

# V4 全量字幕 + Agent 自主调用视觉
python evaluation/eval_v4_agent.py          # 约 20min

# 辅助
python evaluation/retry_failed.py           # 重判失败的裁判记录
```

**抽帧说明**：V3/V4 的画面评测优先使用 `项目文档/评测/视频/` 下的本地视频文件，
找不到时回退到从 URL 拉流。
